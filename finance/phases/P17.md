## What shipped

- **Categories** (`/more/categories`) — grouped list, default include-in-budget switch, add / rename / archive. Usage count + essential flag. Merge is out of scope.
- **Settings → Money** (`/more/settings`) — default monthly budget, expected salary, salary day, EF months, essentials multi-select. Changing the default budget fills months with **no cap row**; existing month caps stay.
- **Privacy blur** — Home eye icon; Settings “blur Home numbers by default”. Amounts still compute.
- **PWA** — installable standalone (manifest + pass-through service worker from Phase 1), safe-area padding, Add to Home Screen offer on the second visit (iOS gets Share-sheet copy).
- **Tailnet front door** — `/api/*` (except `/api/health`) can require `Tailscale-User-Login`. Public bind (`0.0.0.0`) is refused unless Tailscale is required or `FINANCE_ALLOW_UNAUTH=1`.
- **PIN / biometric** — Settings → Security. PIN is hashed (scrypt) in SQLite `meta`. Unlock overlay on this phone; auto-lock interval. Biometrics are per-device WebAuthn. The API is still the tailnet, not the PIN.
- **Empty / error copy** — laptop-down + Retry on Home, Ledger, Plan, Accounts, Categories, Settings, account/ledger detail, Reconcile, Quick Add. Offline reads are **not** stored on the phone.

Out of scope as planned: category merge, notifications, export/backup (Phase 23), Allocate confirm (Phase 19), Wealth (Phase 18), writing either Excel file, IndexedDB, vite-plugin-pwa (the Phase 1 service worker already makes Chromium treat it as installable).

## How to run

```bash
cd "/home/himanshu/Documents/project-tool-scripts-whatnot/toolkit/finance/new proper web app/app"
npm run dev
```

Open **`http://127.0.0.1:5173/more/categories`** and **`/more/settings`**.

1. Add or rename a category. Toggle **Budget** — a new Quick Add expense in that category should default to in-budget; old ledger rows stay as they were.
2. Settings → default monthly budget. Open Plan on a **future** month that has no cap of its own (e.g. a month you have not edited). The cap should be the new default. This month, if it already has a cap row, should not move.
3. Home eye: amounts blur; pace / free cash still sit in the same cards. Settings “blur by default” survives a reload until you un-blur for the session.
4. Optional: set a PIN. Reloading the tab should show the lock overlay. Unlock. Numbers still come from `/api`, not the phone.
5. Install from the **HTTPS** Tailscale URL (second visit, or browser Install app). Quick Add an expense. Restart the server — the row is still there (`data/finance.sqlite`). Clearing site data does **not** delete it.

Phone: `tailscale serve 5173`, then **`https://omarchy.tailf7a628.ts.net/more/settings`**.

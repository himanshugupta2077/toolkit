## What shipped

- **Portfolio** (`/wealth/portfolio`) — value hero (current / invested / gain), 1M–All sparkline, allocation drift bars vs the current plan, holdings list, FDs with optional maturity.
- **Holdings** — asset + account. Units are micro-units (× 10⁶). Buys store units/NAV/amount and a ledger row. **Update NAV** is a manual rupee field. Value = units × NAV when NAV is set, else cost. Gain = value − cost.
- **Mark-to-market** — on accounts that have holdings, `balance = ledger − cost + value`. Manual NAV therefore changes current value **and** net worth. No NAV → no change (cost).
- **Allocation drift** — actual % from holding values vs active plan weights (matched by id, then name). **Rebalance** when |drift| > 5 percentage points.
- **Snapshots** — `snapshots` + `net_worth_daily`. First open of the day (Wealth / Portfolio) writes a point. Confirmed Allocate, NAV update, dip deploy, and **Snapshot** upsert today. Nightly backup cron stays Phase 23.
- **FDs** — listed as holdings from `account_group=fd`. Optional **maturity date** on the account form; caption is “matures in N days”.
- **Dip deploy** — if a holding exists on that asset + To account and last NAV is set, also writes a `buy_dip` txn.

Approval cases:

- Manual NAV update changes current value and net worth.
- Snapshot after an allocate run shows a new point on the chart (yesterday + today).
- Drift bars match holdings vs plan weights (₹9,000 / ₹1,000 → 90% / 10% with rebalance hints).

## What shipped

Your budget workbook can be uploaded into SQLite. The engine is unchanged. Product tabs are still Phase 1 placeholders. The new work is **server-side SheetJS parse + one-transaction insert + a balance match report** on `/dev/store`.

- **`POST /api/import/finance`** — multipart field `file` (`.xlsx`) and `replace` (`true`/`false`). Server parses, inserts, returns JSON.
- **Configuration** — accounts (type, opening, limit, net-worth, liquid, group), categories (group, typical budget), default cap, monthly salary.
- **Ledger** — Excel serial → ISO date; `Source=excel`; blank Include-in-budget → category default. Historical Type Guide misses are **imported anyway** (warnings in the report) so balances can match the sheet.
- **Monthly Budget** — month caps only (derived columns ignored).
- **Planned Expenses** — recurring (Kind, Active, Start/End, payment-method aliases), one-time, expected inflows.
- **Reconciliation** — actual / last-checked / notes as first `reconciliations` rows (new migration `0001`).
- **One transaction.** Ledger idempotency via `source_hash` (duplicate identical rows get `:2`, `:3`, …). Re-import while Excel is still in use skips hashes that already exist. Plans and reconcile rows are replaced on each import (no product editor yet).
- **Validation report** — per account, sheet formula (opening ± ledger by name) vs engine after insert. Green if |delta| ≤ ₹1. Click a row for that account’s imported ledger lines. Also shows Sep Loan/EMI and whether MacBook SmartEMI is in it.

Wipe-first is a checkbox (on by default). Dummy expenses stay if you leave it off and will show as mismatches. **Skip import** keeps the Phase 9 seed catalog.

Does **not** write the live Excel file. Investment xlsx is Phase 11.

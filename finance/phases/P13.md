# Phase 13 — Ledger screen (approved)

Implemented 2026-09-06. Approved 2026-09-06 (you asked to start Phase 14).

## What shipped

The Ledger tab is a real month list over SQLite, not a placeholder.

- **Month switcher** — ← September 2026 → (next month disabled when you are on the current IST month).
- **Summary strip** for the current filter: In · Out · Budget spend.
- **Day-grouped list** — sticky day header (`Sun 6 Sep · ₹50.00 out`). Each row: category initial, note or category name, account chip, amount (red out / green in / grey transfer), **B** if in-budget.
- **Search** (note, category, account, amount) and a **Filters** sheet: type, account, category, in-budget, source. Badge shows how many sheet filters are on. URL keeps the month + filters (`/ledger?month=2026-09&q=care`).
- **Detail page** (`/ledger/:id`) — fields, provenance (source, created/updated), “why is this not in budget?”, Edit / Duplicate / Delete. No balance to type.
- **Edit** — same Type Guide as Quick Add; `PATCH /api/ledger/:id`. Illegal From/To is an inline hint, not a silent save.
- **Duplicate** — posts a new manual row dated today.
- **Delete** — confirm, then soft-delete (`deleted_at`). The row leaves the list; month spend and account balances move. Reopening SQLite still has the row, marked deleted.

`POST /api/ledger` from Quick Add invalidates this list, so a new capture shows up without a manual refresh.

Out of scope as planned: swipe delete/duplicate (skip — it would eat the phase), long-press bulk edit, saved filter pills, infinite-scroll into earlier months (use the month switcher), amount-range / has-note filters.
